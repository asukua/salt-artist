# 艺人页设计：0.1.5

## 目标与数据边界

页面继续参考用户提供的 Apple Music 艺人页截图，保留大幅写真、居中信息与主播放、紧凑歌曲列和响应式专辑网格。0.1.5 增加可关闭的艺人多语言别名识别，只用于 Apple Music 头图、头像和资料的身份选择。宿主曲库标签、艺人条目、收藏分组、原始编辑键与歌曲聚合保持原语义，不因别名识别合并歌曲。

艺人资料与曲库统计分别标明来源。出生、成立、来自等生平字段仅使用 Apple Music 的公开资料或页面数据，缺失则隐藏；曲库年份不表示出生年份。完全没有可显示的 Apple Music 文字资料时，恢复 0.1.2 的曲库统计小面板：名称、曲数与专辑数、年份范围、库流派，并明确标注来源为曲库。此时不再展示仅含姓名的空白小面板。

曲库没有播放热度数据，歌曲不包装成热门榜单。「最新添加」沿用宿主 `Track.addedTime`；1.19.1 的该值来自文件创建时间，并非精确扫描入库时刻，卡片不显示具体添加日期，也不以发行年份替代。

## Apple Music 身份与别名

规范化后的完整名字相等仍可能选中同名艺人，不能把搜索第一项或语言相似当作身份依据。已核对的案例：`初音未来` 的严格名字候选可能指向另一 ID `1617064435`，目标 Hatsune Miku 为 `307078957`；`Jay Chou`、`周杰伦` 与 `周杰倫` 对应同一 ID `300117743`。内置别名绑定以这些已核实的官方身份为依据，不生成任意音译或翻译。

当前内置 6 组已核实的绑定，使用前仍实时 lookup 确认指定 ID 存在，并命中至少一个组内官方名字：

| --- | --- |
| 初音ミク / 初音未来 / 初音未來 / Hatsune Miku | `307078957` |
| 周杰伦 / 周杰倫 / Jay Chou | `300117743` |
| 陈奕迅 / 陳奕迅 / Eason Chan | `137938148` |
| 林俊杰 / 林俊傑 / JJ Lin | `216635866` |

| 邓紫棋 / 鄧紫棋 / G.E.M. | `425208570` |

`recognize_artist_aliases` 默认开启。选择顺序为：手动绑定 → 内置已核实别名与指定 ID → 普通完整名字或官方跨地区名称验证，只接受唯一有效候选。手动绑定代表用户明确选择目标，只验证返回 ID 与指定值一致；无效或冲突条目拒绝。没有完整名字匹配时，通用候选超过 3 个直接拒绝，至多 3 个才进行官方 lookup 与目标 header 核验。没有充分证据或候选歧义时保留既有本地/曲库图片回退，不借用猜测艺人的资料，不做 fuzzy 或搜索排名猜测。

开启模式的通用三地区查询必须区分「有效空结果」与「请求失败或响应不合法」。任一地区未知时不能证明候选唯一，应直接回退；手动或内置指定 ID 仍按各自的 ID 验证路径处理。内置 canonical ID 验证失败时也不能继续用普通同名搜索兜底，否则会重新选中已知错误的同名艺人。

`artist_identity_overrides` 为设置文本框，格式为「曲库艺人名=Apple Music 官方 HTTPS 艺人链接或纯 ID」，链接形如 `https://music.apple.com/{store}/artist/[slug/]ID`；多项使用英文分号或换行，例如 `初音未来=307078957;周杰伦=300117743`。该映射关联原始曲库艺人名，不重命名显示条目，也不改变保存编辑与收藏时的身份。

链接解析必须验证官方域名与完整艺人路径，不能从任意包含 `artist` 或尾部数字的路径宽松截取 ID。完整路径限制与 canonical 验证失败后的回退约束均有针对性测试。

手动绑定需要开启别名识别，关闭开关时手动与自动绑定均忽略。身份键仅规范化宽度、大小写与空白，保留标点后取 SHA 指纹；关闭时 namespace 包含原名 SHA + `strict-v1`，开启时包含原名 SHA + `aliases-v1` + 手动绑定摘要。两种模式均区分 `AC/DC` 与 `AC DC`，不能继续仅用折叠标点的艺人名作 AM 缓存键。

0.1.4 的旧 name-only 缓存没有足够身份信息，0.1.5 不复用这些元数据或图片，升级后按需重新确认一次，无需用户手动清理。旧 v2/v3 记录仍可解码，但不代表旧 namespace 可作为新策略命中；新 namespace 下各语言缓存仍可落盘并重载。开关与手动绑定内容隔离元数据、大图、头像的成功与失败结果；刷新某艺人时清除该原名下全部策略 namespace。头图、头像与资料共用同一识别策略。

## 资料语言与回退

首选语言可设为 `CHINESE`、`ENGLISH` 或 `JAPANESE`，默认中文。`showOtherLanguages` 默认开启：首选语言没有资料时允许显示其他可用语言的原文；关闭后按所选语言筛选，不自动翻译或补造内容。身份识别 namespace 内的资料缓存再按艺人与语言区分；切换首选语言或回退设置后应用新的偏好，不能继续展示不符合当前设置的旧选择。日期仍沿用中文格式，语言偏好控制资料选择而非自动翻译界面。

显式中文 URL 不保证返回中文正文；实际为英文时标记为 EN，并尝试原生 US `en-US` 页。只有允许其他语言时才展示这种降级资料；中文偏好关闭语言回退时，也过滤未翻译的来自和流派。某些艺人在中文页没有简介、英语页却有原文，不能把这种情况当作全部资料缺失或生成中文简介。

中文页的结构化数据可能提前包含英文简介，这段降级资料不能抢占显式 US `en-US` 页的英语选择；0.1.4 语言测试拦住该问题后修正了来源优先级，不能改回全局取首段可用简介。

公开页面按目标艺人 ID 绑定 header、结构化数据和简介，避免取到推荐艺人的图片或文字。公开资料接口补充基础字段；app bearer 从当前公开网页资产动态发现，仅存内存，不落盘、不写日志，不要求用户登录。字段缺失正常回退，不能假设所有艺人都有完整中文资料。远程资料请求与本地照片、封面解码保持独立后台任务。

## 1.19.1 艺人总列表扩展

沿用的列表增强依据宿主 1.19.1 的字节码与当前 Compose 内部契约设计，仍待用户手动验收。目标是在不改变宿主数据源、布局尺寸和点击行为的前提下，提供收藏优先和 Apple Music 小圆头像；任何守卫失败都保留原生行为。0.1.5 的别名识别只改变头像资源的目标，不重排或合并艺人条目。

`favoritesFirst` 默认开启，使用稳定分组：收藏艺人置前，收藏组和其余组内部各自保留宿主原顺序。关闭时沿用原始顺序；不修改宿主的 List 或 Flow，不给其他页面的数据消费者重排源数据。

排序接入采用官方 `appendContent` 包裹原 grid DSL。先从本次临时 `LazyGridIntervalContent` 读取 `intervals`，在契约守卫通过后生成索引映射，复用原有 `key`、`contentType` 和 `itemContent`。完整映射准备好后，原子替换本次临时 builder 的引用，使一次构建使用一致的映射；失败时不留下部分重排。

`ComposableLambdaImpl` 同时实现多个 FunctionN 接口，普通 Kotlin 函数类型转换还会检查 arity，曾误拒绝符合 grid JVM 契约的回调。现先用 Java `Function4.isInstance` 验证接口，再使用泛型擦除转换；真实 `invoke` 签名已对照宿主与依赖，升级时须保留这一核查。该问题由真实 Compose interval builder 测试发现并修复。

没有采用以下两条已核对过的路径：`after.setResult` 的结果未被宿主回写，不能改变最终 grid 内容；`replaceGrid` 在该调用点被 `defaultMask=1008` 跳过。使用临时 builder 映射是针对这些约束的选择，并不表示 Compose 内部结构是稳定公开 API。宿主或 Compose 升级时必须重新核查该契约与守卫，不能只扩大版本范围。

头像接入保留原生 48dp 头像的绘制与测量，不替换原生 Composable。`afterComposable` 追加零宽、48dp 高的容器，在内部绘制固定圆图覆盖原头像。字节码已确认目标父 Row 使用 Start 排列并有显式 Spacer，因此设计上不重新分配水平空间；原有点击仍由宿主维持。零宽覆盖的实际对齐、裁剪和点击保持仍需在目标宿主运行验证。

## 列表头像加载约束

列表小头像走独立轻量路径：仅可见项按需请求 128px 图片，使用磁盘缓存，单个网络 worker 渐进加载并节流。0.1.5 在身份解析中应用同一别名与手动绑定策略，再读取目标公开页的头像元数据；仍不访问资料接口或大型网页脚本，也不下载 hero 大图。

没有合适的 Apple Music 图、请求失败或图片尚未就绪时，不遮住原生曲库封面。加载成功后才显示覆盖图。此回退与稳定排序分别受守卫约束，不能因头像不可得而丢掉列表项或改变点击对象。

## 艺人页沿用的约束

0.1.3 将顶栏右侧改为直接搜索，复制摘要移入更多菜单；「自定义艺术字」支持透明 PNG/WebP 的解码验证、预览与恢复默认，路径丢失也能恢复。自定义图片、艺术字、显示名与曲目覆盖使用原始艺人键保存；编辑器保留隐藏原曲与手动添加曲目的快照，别名和歌曲 ID、原始专辑键分开。

0.1.1 的标题已经居中，但主播放与随机播放位于分离的偏左动作区，其他操作集中在顶栏胶囊；0.1.2 将主信息和动作聚合到中心。写真沿用宽范围渐隐，从照片下缘取色，调暗时保留色相；清晰层、模糊层与背景共同收敛到同一底色，避免短渐变或硬色块强调横向接缝。遮罩位于照片和背景层，保持文字可读。专辑网格按内容宽度 1100/860/620dp 对应六/五/四列，更窄时两列。

侧边栏和系统标题栏仍在艺人页槽位之外。主页面的 `afterComposable`、权限描述符和逐版混淆映射以 [宿主兼容记录](host-compatibility.md) 为准；新增的列表接入契约见本记录。配置页「暗色背景」尚未被页面消费，仍为已知问题。

添加时间不依赖 `RepoService.snapshotTracks`：0.1.3 首候选显示 255 首曲目但已知添加时间为 0，字节码确认该快照由独立流程更新。现有路径在公开曲库读取成功后，复用 Library 实现的原始只读 Track 查询，后台适配立即结果或挂起 Continuation，8 秒超时后降级；缓存绑定曲目列表身份，并通过加载代次丢弃过期回调。

## 验证范围

0.1.5 已通过 81 项自动测试，覆盖 strict 标点隔离、错误旧 ID 拒绝、内置 ID 错名拒绝、URL 路径限制、地区未知响应回退与同 namespace 语言缓存重载。真实 Compose interval builder 测试覆盖临时 builder 交换、原 key/内容类型保持及守卫失败回退；自动测试不等于所有宿主渠道或交互均已验证。

构建要求、Release 与校验文件见 [README](../README.md)。包根与 `classes/` 的 Manifest 保持一致，权限为 `class-transform,library-read`，不打入宿主运行时与测试依赖。字节码与 builder 契约的本地复核输出位于 `build/reports/host-compatibility/1.19.1/directory/`。

身份切换、图片加载、零宽头像覆盖、收藏排序、窗口缩放、快速切换和缺图场景仍需在目标宿主运行检查。历史运行结论与目标映射见 [兼容记录](host-compatibility.md)，不以旧版截图替代当前验证。本文件是身份选择与列表扩展的单一维护入口。
