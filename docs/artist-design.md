# 艺人页设计：0.1.9

## 0.1.9 动态渲染替换

用户确认 0.1.7 开启动态头图退出、关闭则不退出，将问题定位到动态路径，但没有定位到单条 native 崩溃指令。0.1.9 移除宿主视频 Surface、反射 Composable 和共享 GPU 视频纹理接入，恢复配置开关，使用独立 libmpv C API 实例（vo=null、hwdec=no、音轨关闭）读取 screenshot-raw CPU 帧，再通过普通 Skia raster Image 绘制。主机 GPU 仍负责普通 UI 绘制，但不再接收解码器的共享纹理或跨库视频 Surface。

MediaMP JNI handle 是包装对象地址，不能当作 libmpv C API handle。实现只用 mpv_create 返回的独立 handle，按 [mpv 官方 client.h](https://github.com/mpv-player/mpv/blob/master/include/mpv/client.h) 的 x64 mpv_node/map/byte-array ABI 读取、复制并释放结果；不访问 MediaMP 包装对象内部内存。宿主 factory 仅用于加载已有 native 库，随即关闭，不创建 Surface。JNA 仅 compileOnly，未打入插件。

每秒最多取 10 帧，优先较小 H.264 SDR 流，像素/stride/字节数校验后复制到 JVM 数组。OwnedMotionFrame 在替换、绘制和释放间互斥；绘制方法返回后才释放旧 raster Image，关闭后晚到帧立即释放，不积累逐帧位图。解码与销毁在后台进行，窗口失焦、切页、插件停用均结束会话。

隔离 probe 已取得 Gorillaz 24 张内容不同的真实 CPU 帧，并经过 Skia raster Image 编码输出 PNG，确认通道与画面正确，不再只验证播放时钟。未操作宿主应用；实际宿主动态页面仍需用户验收。证据在 build/reports/motion-research/raw-probe.log、cpu-frame.png。下文 0.1.7 的 GPU Surface 设计仅为历史，不是当前播放路径。

最终生产类另完成 3 轮独立创建、取帧、销毁，每轮取得 5 帧；结果在 raw-probe-final.log。125 项自动测试及打包检查通过，新增覆盖绘制过程中禁止释放帧、替换与停用后迟到帧仅释放一次。测试、隔离 CPU 绘制验证与宿主实际验收仍分别记录。

## 0.1.8 退出问题的安全处置

用户报告 0.1.7 加载头图退出，动态头图尤其明显。本机日志有多次素材解析后重新启动的记录，但没有同期 JVM 错误栈或 dump，尚不能确认全部退出原因。无窗口解码成功仅证明解码器可用，未覆盖 Compose GPU 共享纹理及实际渲染，不足以据此将动态播放默认启用。

0.1.8 在页面选择和播放器入口两处禁止动态播放，移除配置入口，旧配置为 true 也不能创建 native player。保持动态素材解析、当前静态封面、手动匹配和地区重试。下面的动态播放实现说明保留为 0.1.7 的历史设计；恢复前须取得实际 GPU 页面与释放场景的验证，不能只重开开关。

静态图片路径同时降低内存压力：取色使用 ImageIO 子采样后的最长边 256px 图片，不再完整展开原图；头图/本地写真各限制 4 项、logo 8 项、封面 128 项，封面缩至 640px 且不生成五档模糊。限制编码图片为 32 MiB、源像素为 3600 万，拒绝时沿用页面回退。缓存淘汰只释放持有引用，不对可能仍在绘制的 ImageBitmap 手工 close。此改动是对可见内存风险的防护，不作为已经证明 OOM 根因的结论。

0.1.8 通过 123 项自动测试与打包检查，新增覆盖动态入口被禁用、图片子采样与像素上限、缓存淘汰后消费者引用保持。未启动宿主复现，不能宣称已确认消除所有闪退。

## 目标与数据边界

页面继续参考用户提供的 Apple Music 艺人页截图，保留大幅写真、居中信息与主播放、紧凑歌曲列和响应式专辑网格。0.1.7 增加交互式 Apple Music 艺人匹配、地区重试设置与可关闭的动态头图。身份识别只用于 Apple Music 素材与资料的选择；宿主曲库标签、艺人条目、收藏分组、原始编辑键与歌曲聚合保持原语义，不因别名识别合并歌曲。

艺人资料与曲库统计分别标明来源。出生、成立、来自等生平字段仅使用 Apple Music 的公开资料或页面数据，缺失则隐藏；曲库年份不表示出生年份。完全没有可显示的 Apple Music 文字资料时，恢复 0.1.2 的曲库统计小面板：名称、曲数与专辑数、年份范围、库流派，并明确标注来源为曲库。此时不再展示仅含姓名的空白小面板。

曲库没有播放热度数据，歌曲不包装成热门榜单。「最新添加」沿用宿主 `Track.addedTime`；1.19.1 的该值来自文件创建时间，并非精确扫描入库时刻，卡片不显示具体添加日期，也不以发行年份替代。

## Apple Music 身份与别名

规范化后的完整名字相等仍可能选中同名艺人，不能把搜索第一项或语言相似当作身份依据。已核对的案例：`初音未来` 的严格名字候选可能指向另一 ID `1617064435`，目标 Hatsune Miku 为 `307078957`；`Jay Chou`、`周杰伦` 与 `周杰倫` 对应同一 ID `300117743`。内置别名绑定以这些已核实的官方身份为依据，不生成任意音译或翻译。

0.1.7 实际搜索观察到 `Gorillaz` 同时对应 `567072` 和另一 ID `1529389870`；经当前官方艺人页核实后加入指定 ID，避免使用搜索排名消解这项已知歧义。未核实的同名冲突仍交给用户显式选择。

`recognize_artist_aliases` 默认开启。选择顺序为：手动绑定 → 内置已核实别名与指定 ID → 普通完整名字或官方跨地区名称验证，只接受唯一有效候选。手动绑定代表用户明确选择目标，只验证返回 ID 与指定值一致；无效或冲突条目拒绝。没有完整名字匹配时，通用候选超过 3 个直接拒绝，至多 3 个才进行官方 lookup 与目标 header 核验。没有充分证据或候选歧义时保留既有本地/曲库图片回退，不借用猜测艺人的资料，不做 fuzzy 或搜索排名猜测。

0.1.7 改为遇到某地区请求失败或响应不合法时继续尝试后续地区，避免一次 US 传输故障阻断其他可用地区。只依据已返回且结构有效的结果去重；失败响应不制造候选，也不表示该地区没有同名艺人。已观察到同名对应多个 ID 时仍拒绝自动选择，有效空 `results: []` 与失败响应分别处理。此策略替代 0.1.6 的「任一地区未知就整体回退」约束，取舍是接受可用地区的证据，不宣称已穷尽全部地区。手动或内置指定 ID 仍按各自的 ID 验证路径处理；内置 canonical ID 验证失败时不能用普通同名搜索兜底，否则会重新选中已知错误的同名艺人。

更多菜单的「匹配 Apple Music 艺人」提供显式选择：可按名字搜索，展示相似候选，或输入官方艺人链接、纯 ID。搜索候选不代表自动确认，用户选择后才写入当前原始曲库名的绑定；可删除该绑定恢复自动匹配。保存选择时若别名识别已关闭，会同时开启识别。该入口不重命名艺人、不改变曲目聚合，也不把相似搜索用于后台自动猜测。

`artist_identity_overrides` 为设置文本框，格式为「曲库艺人名=Apple Music 官方 HTTPS 艺人链接或纯 ID」，链接形如 `https://music.apple.com/{store}/artist/[slug/]ID`；多项使用英文分号或换行，例如 `初音未来=307078957;周杰伦=300117743`。该映射关联原始曲库艺人名，不重命名显示条目，也不改变保存编辑与收藏时的身份。

链接解析必须验证官方域名与完整艺人路径，不能从任意包含 `artist` 或尾部数字的路径宽松截取 ID。完整路径限制与 canonical 验证失败后的回退约束均有针对性测试。

手动绑定需要开启别名识别，关闭开关时手动与自动绑定均忽略。身份键规范化宽度、大小写与空白，清除常见不可见分隔符，保留标点后取 SHA 指纹。0.1.7 的 namespace 包含原名 SHA、`strict-v2` 或 `aliases-v2`、规范化的地区顺序，开启模式还包含手动绑定摘要。两种模式均区分 `AC/DC` 与 `AC DC`，不能仅用折叠标点的艺人名作 AM 缓存键。

0.1.4 的旧 name-only 缓存没有足够身份信息，后续版本不复用这些记录作为新策略身份。0.1.7 再以策略 v2 隔离旧策略结果，升级后按需重新确认，无需用户手动清理。旧格式仍可解码，但不代表旧 namespace 可作为新策略命中；同一 namespace 下各语言缓存仍可落盘并重载。开关、地区顺序与手动绑定内容共同隔离元数据、大图、头像的成功与失败结果；刷新某艺人时清除该原名下全部策略 namespace。头图、头像与资料共用同一不可变识别策略，后台请求晚到也写回其原策略缓存。

## 地区顺序与传输回退

`apple_music_storefronts` 默认 `US,JP,CN`。配置接受最多 8 个不同的合法 ISO 两字母地区代码，保留用户顺序；无有效输入时恢复默认。地区顺序参与身份 namespace，资料语言独立控制页面或公开资料接口的 locale，选 CN 不等于强制中文，也不能假设 US 页面只包含英语。

仅默认地区顺序启用临时 US 健康回退：US 网络请求失败或响应不合法后，本次接着先尝试 CN、再 JP，随后 5 分钟暂避 US。有效的空搜索列表不触发暂避；没有某艺人或没有某字段也不能直接当作地区网络故障。自定义地区顺序按配置尝试，不被该默认策略重排。

地区健康只是内存中的短期传输状态，不写入配置、资料或图片缓存的 namespace。它不能改写艺人 ID、资料语言或永久覆盖用户选择；配置的地区顺序本身才是缓存身份的一部分。

## 资料语言与回退

首选语言可设为 `CHINESE`、`ENGLISH` 或 `JAPANESE`，默认中文。`showOtherLanguages` 默认开启：首选语言没有资料时允许显示其他可用语言的原文；关闭后按所选语言筛选，不自动翻译或补造内容。身份识别 namespace 内的资料缓存再按艺人与语言区分；切换首选语言或回退设置后应用新的偏好，不能继续展示不符合当前设置的旧选择。日期仍沿用中文格式，语言偏好控制资料选择而非自动翻译界面。

显式中文 URL 不保证返回中文正文；实际为英文时标记为 EN，并尝试原生 US `en-US` 页。只有允许其他语言时才展示这种降级资料；中文偏好关闭语言回退时，也过滤未翻译的来自和流派。某些艺人在中文页没有简介、英语页却有原文，不能把这种情况当作全部资料缺失或生成中文简介。

中文页的结构化数据可能提前包含英文简介，这段降级资料不能抢占显式 US `en-US` 页的英语选择；0.1.4 语言测试拦住该问题后修正了来源优先级，不能改回全局取首段可用简介。

公开页面按目标艺人 ID 绑定 header、结构化数据和简介，避免取到推荐艺人的图片或文字。公开资料接口补充基础字段；app bearer 从当前公开网页资产动态发现，仅存内存，不落盘、不写日志，不要求用户登录。字段缺失正常回退，不能假设所有艺人都有完整中文资料。远程资料请求与本地照片、封面解码保持独立后台任务。

## 当前 poster 与动态头图

动态素材只从目标 `ArtistDetailPageIntent` 下唯一且 ID 一致的 `artistDetailHeader` 读取。优先 `wideVideoArtwork.dictionary.motionArtistFullscreen16x9`，再尝试 `motionArtistWide16x9` 和 `videoArtwork.motionArtistSquare1x1`，将同一 variant 的 `video` 与 `previewFrame.url` 绑定；不在推荐区或整页文本中寻找视频。

公开 [Gorillaz 艺人页](https://music.apple.com/us/artist/gorillaz/567072?l=en-US) 的 US、CN、JP header 已核实同时包含旧 `wideArtwork` 和新的动态 variant。旧解析无条件优先静态横图，因此即使页面已换动态素材，插件仍会显示旧图。0.1.7 优先当前动画的官方 poster，关闭动画也使用这一静态图；poster 是官方提供的预览画面，不保证等于视频解码的第零帧。

元数据的可选 `AmArtistMotion` 保存 HLS/MP4 类型、视频 URL 和同 variant 的 poster；`motionCheckedAt` 区分「已检查且没有动画」与旧版、仅头像缓存的「尚未检查」。v4 缓存使用固定 24 列，兼容读取旧 8 列、v2/v3 的图片与资料，但旧记录需要补查一次 header。动态开关不参与元数据身份，不因开关反复抓取同一艺人的资料。

URL 只接受已知 Apple CDN 的 HTTPS HLS/MP4 和图片模板，拒绝本地协议、外部域、账号信息、非默认端口与过长 URL；页面与缓存行也有大小限制。实测 Gorillaz master 提供 SDR H.264 与 HEVC 多码率 variant，播放器优先普通 H.264 SDR 视频流，不能把 I-frame trick-play 列表误当完整动画。最小无简介网络证据保存在本地 `build/reports/apple-music-motion/`，不随包分发第三方视频。

`animated_artist_hero` 默认开启，仅当当前素材来自 AM 且没有自定义照片时尝试播放。复用宿主 mediamp/mpv，以独立播放器静音循环，不修改音乐播放队列、不新增解码器或视频分发包。poster 位于动画下方，待实际帧就绪后再显示视频；失败保留 poster。动画与静态图共用底缘渐隐和裁剪，头图滚出约 60% 或窗口失焦时离开组合并释放资源，重新进入时按当前艺人素材建立会话。

隔离无窗口 harness 已验证宿主 factory 自行加载内置 native 库，无额外库路径或解码器安装；Gorillaz 的 H.264 1024×576 视频解码时间持续推进，音轨关闭、静音和循环参数被接受。Surface 的字节码已确认直接消费 native 视频纹理，不依赖未设置的 high-level currentMedia。此验证未创建 Compose GPU 页面，实际画面与交互仍由用户验收。宿主反射 ABI 与失败边界见 [兼容记录](host-compatibility.md#动态头图运行时约束)。

## 艺人总列表扩展

沿用的列表增强依据宿主 1.19.1 的字节码与当前 Compose 内部契约设计，0.1.6 已复核 1.19.2 的相关目录与 Compose class 字节未变，仍待用户手动验收。目标是在不改变宿主数据源、布局尺寸和点击行为的前提下，提供收藏优先和 Apple Music 小圆头像；任何守卫失败都保留原生行为。0.1.5 的别名识别只改变头像资源的目标，不重排或合并艺人条目。

`favoritesFirst` 默认开启，使用稳定分组：收藏艺人置前，收藏组和其余组内部各自保留宿主原顺序。关闭时沿用原始顺序；不修改宿主的 List 或 Flow，不给其他页面的数据消费者重排源数据。

排序接入采用官方 `appendContent` 包裹原 grid DSL。先从本次临时 `LazyGridIntervalContent` 读取 `intervals`，在契约守卫通过后生成索引映射，复用原有 `key`、`contentType` 和 `itemContent`。完整映射准备好后，原子替换本次临时 builder 的引用，使一次构建使用一致的映射；失败时不留下部分重排。

`ComposableLambdaImpl` 同时实现多个 FunctionN 接口，普通 Kotlin 函数类型转换还会检查 arity，曾误拒绝符合 grid JVM 契约的回调。现先用 Java `Function4.isInstance` 验证接口，再使用泛型擦除转换；真实 `invoke` 签名已对照宿主与依赖，升级时须保留这一核查。该问题由真实 Compose interval builder 测试发现并修复。

没有采用以下两条已核对过的路径：`after.setResult` 的结果未被宿主回写，不能改变最终 grid 内容；`replaceGrid` 在该调用点被 `defaultMask=1008` 跳过。使用临时 builder 映射是针对这些约束的选择，并不表示 Compose 内部结构是稳定公开 API。宿主或 Compose 升级时必须重新核查该契约与守卫，不能只扩大版本范围。

头像接入保留原生 48dp 头像的绘制与测量，不替换原生 Composable。`afterComposable` 追加零宽、48dp 高的容器，在内部绘制固定圆图覆盖原头像。字节码已确认目标父 Row 使用 Start 排列并有显式 Spacer，因此设计上不重新分配水平空间；原有点击仍由宿主维持。零宽覆盖的实际对齐、裁剪和点击保持仍需在目标宿主运行验证。

## 列表头像加载约束

列表小头像走独立轻量路径：仅可见项按需请求 128px 图片，使用磁盘缓存，单个网络 worker 渐进加载并节流。0.1.5 在身份解析中应用同一别名与手动绑定策略，再读取目标公开页的头像元数据；仍不访问资料接口或大型网页脚本，也不下载 hero 大图。

没有合适的 Apple Music 图、请求失败或图片尚未就绪时，不遮住原生曲库封面。加载成功后才显示覆盖图。此回退与稳定排序分别受守卫约束，不能因头像不可得而丢掉列表项或改变点击对象。

## 艺人页沿用的约束

0.1.3 将顶栏右侧改为直接搜索，复制摘要移入更多菜单；「自定义艺术字」支持透明 PNG/WebP 的解码验证、预览与恢复默认，路径丢失也能恢复。自定义图片、艺术字、显示名与曲目覆盖使用原始艺人键保存；编辑器保留隐藏原曲与手动添加曲目的快照，别名和歌曲 ID、原始专辑键分开。

0.1.1 的标题已经居中，但主播放与随机播放位于分离的偏左动作区，其他操作集中在顶栏胶囊；0.1.2 将主信息和动作聚合到中心。写真沿用宽范围渐隐，从照片下缘取色，调暗时保留色相；清晰层、模糊层与背景共同收敛到同一底色，避免短渐变或硬色块强调横向接缝。遮罩位于照片和背景层，保持文字可读。专辑网格按内容宽度 1100/860/620dp 对应六/五/四列，更窄时两列。

侧边栏和系统标题栏仍在艺人页槽位之外。主页面的 `afterComposable`、权限描述符和逐版混淆映射以 [宿主兼容记录](host-compatibility.md) 为准；新增的列表接入契约见本记录。配置页「暗色背景」尚未被页面消费，仍为已知问题。

添加时间不依赖 `RepoService.snapshotTracks`：0.1.3 首候选显示 255 首曲目但已知添加时间为 0，字节码确认该快照由独立流程更新。现有路径在公开曲库读取成功后，复用 Library 实现的原始只读 Track 查询，后台适配立即结果或挂起 Continuation，8 秒超时后降级；缓存绑定曲目列表身份，并通过加载代次丢弃过期回调。
